# Domain docs

This repository uses a single root `CONTEXT.md` glossary and `docs/adr/` for consequential architecture decisions.

Before exploring domain behavior, read `CONTEXT.md` if it exists and ADRs relevant to the work. Proceed silently when those files are absent; create them only when terms or decisions are settled.

Use the glossary's terms in issues, specifications, and code. Record agreed domain terms in the glossary, keeping implementation details in specifications or ADRs. Raise conflicts with existing ADRs explicitly before replacing their decisions.
